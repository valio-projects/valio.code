# valio.code

**Задайте кодовой базе точный вопрос и сохраните свидетельства, на которых
держится ответ.** `valio.code` превращает зафиксированный view проекта в
доступные для поиска исходники, типизированные объявления, связи и ограниченный
контекст для разработчиков и программных агентов.

Проект распространяется по AGPL-3.0 и остаётся развивающимся локальным
вертикальным срезом, а не завершённой v1. Перед использованием возможности
смотрите [статус волны интеллектуального анализа](docs/ru/reference/intelligence-wave.md)
и [справочник анализа языков](docs/ru/reference/language-analysis.md).

[Русская документация](docs/ru/README.md) · [English documentation](README.md)

## Чем это помогает

- Найти исходник, символ, объявление или текст ошибки и сохранить репозиторий и
  неизменяемый view, из которого получен результат.
- Дать агенту ограниченный контекст с привязкой к исходникам и структуре вместо
  выгрузки всего репозитория.
- Объединить лексический BM25, символы, структурных кандидатов по
  нормализованному хешу, эмбеддинги точным cosine, hybrid RRF и необязательный
  reranker.
- Пройти от типа к членам и параметрам, увидеть unresolved observations import
  и call и не принять их за доказанные связи.
- Использовать одинаковые операции в области view через HTTP и 19
  MCP-инструментов.

## Текущий интеллектуальный слой

Go имеет частичный локальный межфайловый анализ через `go/types`. C, C++, C#,
Java, JavaScript, TypeScript, TSX и JSX дают проверенные синтаксические отчёты
и типизированные описания написанных class, struct, interface, enum, членов,
параметров, типов возврата, модификаторов, видимости и raw syntax атрибутов.
`/api/v1/types` и MCP `type_query` выдают их для всех этих языков.

Описания не-Go — синтаксические свидетельства. Они не утверждают
компиляторное разрешение типов, imports, calls или overloads, ABI/layout, поток
данных/управления или вычисленные значения enum. Написанное выражение вроде
`1 << 2` остаётся выражением. `/api/v1/structure/graph` и MCP
`structure_graph` выдают containment объявлений, членов и параметров с явно
неразрешёнными imports и calls. Фрагменты методов не-Go поддерживают
ограниченное расширение контекста родителя.

## Контракты представлений

Восемь версионированных представлений разделяют входы retrieval: code, symbol,
context, documentation, architecture, change, error и API. Текущие producer
создают факты code, symbol, context, documentation, error и API. Architecture и
change пока остаются контрактами без producer и не выдаются как доступные
свидетельства.

JSON-профили поддерживают Ollama, LM Studio/OpenAI-compatible, Docker-host и
удалённые endpoints эмбеддингов. Проверенный локальный smoke использовал
`qwen3-8b-lmstudio-docker` (Q8_0, 4096 измерений), сохранил 29 code embeddings
и выполнил semantic/hybrid retrieval. Это свидетельство интеграции, а не
метрика качества или гарантия удалённого провайдера. Начните с
[примера AI-профилей](deploy/ai-profiles.example.json).

## Статус и оставшаяся работа

Вторая интеграционная волна проверена на Windows полным набором Go-тестов,
`go vet`, реальными SurrealDB 3.2.4 и Jaeger и Compose smoke-сценарием. Docker
также собрал образы API, worker и migration и запустил healthy Compose-сервисы.
Linux Docker `go test -race ./...` прошёл; зависящие от базы тесты в этой Linux
сборке пропускаются.

Для полной v1 ещё нужны семантика уровня SCIP для пяти языков, CFG и
межпроцедурный анализ, связи SQL/API/events, интеллект тестов и истории.
Возможности на основе GNN — исследование после v1.

## Локальный запуск

После установки Docker и Docker Compose выполните из корня репозитория:

```powershell
docker compose up -d --build --wait
```

Откройте <http://127.0.0.1:8080> и используйте локальный токен разработки:

```text
valio-local-development-token-0001
```

Jaeger доступен на <http://127.0.0.1:16686>. Установка, нативный агент и
разработка фронтенда описаны в [руководстве по началу работы](docs/ru/getting-started/installation.md).
