# valio.code

**Задайте кодовой базе точный вопрос и сохраните свидетельства, на которых
держится ответ.** `valio.code` превращает зафиксированный вид проекта в
доступные для поиска исходники, символы, связи и ограниченный контекст для
разработчиков и программных агентов.

Проект распространяется по AGPL-3.0. Текущая реализация — проверенный локальный
вертикальный срез, а не завершённая v1. Перед использованием конкретного
результата анализа смотрите [статус волны интеллектуального анализа](docs/ru/reference/intelligence-wave.md).

[Русская документация](docs/ru/README.md) · [English documentation](README.md)

## Чем это помогает

- Найти реализацию, символ или текст ошибки и не потерять проект и неизменяемый
  view, из которого получен результат.
- Дать агенту небольшой контекст с привязкой к исходникам и связям, а не весь
  репозиторий без границ.
- Объединить точный и лексический поиск с символами, структурными кандидатами,
  семантическим ранжированием, hybrid RRF и необязательным reranker, если
  настроен подходящий профиль модели.
- Исследовать влияние изменений по локальным фактам кода: объявлениям, ссылкам,
  вызовам, чтениям, записям, AST и ограниченному контексту родителя и потомка.
- Использовать одинаковые операции через HTTP и 18 MCP-инструментов, чтобы
  разработчик и агент работали с одними свидетельствами.

## Текущий интеллектуальный слой

Для Go есть локальный межфайловый анализ символов, ссылок, вызовов, чтений и
записей на основе `go/types`; он намеренно неполон для внешних пакетов и
сочетаний build tags. C, C++, C#, Java, JavaScript, TypeScript, TSX и JSX
разбираются WASM-помощником синтаксиса. Их объявления, члены, параметры,
значения enum и атрибуты сохраняются для навигации.

Поиск хранит AST-фрагменты Go и резервное представление других парсеров. Он
ранжирует лексический BM25, символы, структурных кандидатов по нормализованному
хешу и эмбеддинги точным cosine, объединяет кандидатов через RRF и при
необходимости применяет reranker. Результат сохраняет область исходника и
view. Структурные хеши не являются общим MinHash, точный cosine не означает
HNSW, а синтаксические факты не-Go — не компиляторно разрешённые межфайловые
вызовы или поток данных.

Есть восемь версионированных контрактов представлений: code, symbol, context,
documentation, architecture, change, error и API. Текущие producer создают
первые четыре, а также error и API. Для architecture и change producer пока
нет.

JSON-профили AI поддерживают локальные Ollama и LM Studio/OpenAI-compatible,
Docker-host и удалённые endpoints. Квантизованные aliases Qwen3 4B/8B в примере
защищены идентичностью модели и размерности. Настроенный профиль не доказывает,
что удалённая модель работает: её нужно загрузить или импортировать и вызвать
явный probe. Начните с [примера AI-профилей](deploy/ai-profiles.example.json).

## Свидетельства и оставшаяся работа

Интеграционная проверка SurrealDB прошла для graph, retrieval, синтетических
трёхмерных эмбеддингов и парсеров шести не-Go языков. Проверка Docker build/race
ещё шла во время записи волны, поэтому не объявляется успешной. Валидация
реализации записана в `9277db0`, документация — в `641db16`.

До полной v1 остаются семантика уровня SCIP для пяти языков, CFG и
межпроцедурный анализ, связи SQL/API/events, интеллект тестов и истории и
возможности на основе GNN. Подробности — в [матрице приёмки и границах](docs/ru/reference/intelligence-wave.md).

## Локальный запуск

После установки Docker и Docker Compose выполните из корня репозитория:

```powershell
docker compose up -d --build --wait
```

Откройте <http://127.0.0.1:8080> и используйте локальный токен разработки:

```text
valio-local-development-token-0001
```

Jaeger доступен на <http://127.0.0.1:16686>. Установка, нативный агент и
разработка фронтенда описаны в [руководстве по началу работы](docs/ru/getting-started/installation.md).
