# Провайдеры AI-эмбеддингов

Скопируйте [`deploy/ai-profiles.example.json`](../../../deploy/ai-profiles.example.json)
в каталог, которым управляет оператор, и явно выберите профиль. Это строгий
JSON: отклоняются неизвестные поля, данные после JSON, повторяющиеся
идентификаторы, недопустимые адреса, размерности, имена переменных с токеном и
тайм-ауты. Значение токена в файле не хранится: для удалённого провайдера оно
читается только из переменной, указанной в `tokenEnv`.

API один раз загружает `VALIO_AI_CONFIG` при запуске. В поставляемом Compose
файле пример монтируется только для чтения как
`/etc/valio/ai-profiles.json`; после изменения файла API надо перезапустить.
Загрузка конфигурации не обращается к провайдеру, не запускает и не скачивает
модель и не передаёт исходный код.

| Режим провайдера | Базовый адрес в профиле | Путь запроса и размерность |
| --- | --- | --- |
| Ollama на хосте API | `http://127.0.0.1:11434` | `POST /api/embed`; Valio передаёт `dimensions` из профиля и `truncate: false`. |
| LM Studio или другой OpenAI-совместимый сервер | `http://127.0.0.1:1234/v1` | `POST /embeddings`; нативная размерность ответа сервера должна совпадать с профилем. |
| Сервер модели на хосте, доступный из Compose | `http://host.docker.internal:1234/v1` | Тот же OpenAI-совместимый запрос; в примере намеренно указан `allowInsecureHTTP: true`. |
| Удалённый провайдер | `https://…/v1` | `POST /embeddings`; используйте HTTPS и переменную окружения с токеном, если она нужна. |

Значение `allowInsecureHTTP` по умолчанию равно `false`. Указывайте его только
для локального адреса, адреса хоста Docker или сети, которой управляет
оператор. Это не заменяет защищённый транспорт для удалённого провайдера.

Qwen публикует Qwen3 Embedding 4B с размерностью от 32 до 2560 и 8B с
размерностью от 32 до 4096. Профиль закрепляет одну размерность, ревизию
модели, квантизацию, вид представления и косинусное векторное пространство.
Шесть локальных псевдонимов в примере используют размерности выбранных GGUF
артефактов; это не утверждение, что каждая квантизация есть отдельный тег в
библиотеке Ollama. См. официальные карточки Qwen: [4B](https://huggingface.co/Qwen/Qwen3-Embedding-4B)
и [8B](https://huggingface.co/Qwen/Qwen3-Embedding-8B).

Для Ollama `/api/embed` документирует параметры `dimensions` и `truncate`.
Значение `truncate: false` заставляет сервер вернуть ошибку для входа длиннее
контекстного окна вместо неявного изменения входа. [Документация API Ollama](https://docs.ollama.com/api/embed).
У OpenAI-совместимых серверов нет общего контракта на размерность вывода, поэтому
профиль LM Studio закреплён на ожидаемом нативном ответе из 4096 чисел.
Векторы разных профилей не смешиваются.

Чтобы импортировать конкретный официальный GGUF-артефакт, создайте локальный
псевдоним самостоятельно:

```text
# Modelfile: укажите ровно один скачанный официальный GGUF-файл
FROM ./Qwen3-Embedding-4B-Q4_K_M.gguf
```

Выполните `ollama create valio-qwen3-embedding-4b-q4km -f Modelfile`; повторите
для `Q5_K_M`, `Q8_0` и артефакта 8B. Зафиксируйте в профиле точное имя файла,
его дайджест и ревизию.

После загрузки модели намеренно запустите диагностику администратора:

```text
valio-admin ai doctor --config PATH --list
valio-admin ai doctor --config PATH --profile qwen3-8b-q8
```

Сначала команда отдельными запросами только на чтение с тайм-аутом две секунды
проверяет `http://localhost:11434/api/tags` и
`http://localhost:1234/v1/models`. Затем она посылает выбранному профилю один
фиксированный синтетический запрос на эмбеддинг с тайм-аутом из профиля, не
больше 120 секунд. Команда проверяет размерность ответа, но не запускает сервис
и не скачивает модель.

После запуска API использует те же настроенные профили в следующих операциях.
Во всех примерах JSON запрос — обычный текст; для индексирования нельзя
передать адрес провайдера или произвольный исходный код.

```text
POST /api/v1/ai/probe
{"modelProfile":"qwen3-8b-q8"}

POST /api/v1/embeddings/index
{"scope":{"workspaceId":"workspace-main","viewId":"PINNED_VIEW"},"modelProfile":"qwen3-8b-q8","representation":"code","limit":16}

POST /api/v1/retrieval/search
{"scope":{"workspaceId":"workspace-main","viewId":"PINNED_VIEW"},"mode":"semantic","modelProfile":"qwen3-8b-q8","query":"где изменяется User.ID?","limit":20}
```

`/ai/probe` проверяет настроенный провайдер фиксированным синтетическим текстом.
Индексирование берёт только сохранённые и одобренные политикой представления из
закреплённого view. Поле `query` в поиске — обычный текст; результат сохраняет
выбранный профиль и свидетельства ранжирования.

За один запрос индексируются максимум 16 представлений (по умолчанию 8).
Если `complete=false`, передайте возвращённый `nextOffset` как `offset`,
сохраняя view, профиль, вид представления и область проектов. Готовые результаты
сохраняются в SurrealDB и переиспользуются при повторном запросе.

Профили LM Studio используют идентификатор `text-embedding-qwen3-embedding-8b`:
`qwen3-8b-lmstudio-local` для нативного API и `qwen3-8b-lmstudio-docker` для
Compose. Проверьте имя через `GET /v1/models` вашей установки. Локальному
серверу без авторизации параметр `tokenEnv` не требуется.

Для сквозной проверки запустите `scripts/smoke.ps1`, затем передайте выведенные
идентификаторы в `scripts/smoke-ai.ps1 -ProjectId PROJECT -ViewId VIEW`.
Второй скрипт проверяет модель, сохраняет embeddings учебного проекта и
проверяет semantic/hybrid search. Ему нужна работающая модель; он отделён от
проверок CI, не требующих внешнего провайдера.
