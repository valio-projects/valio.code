# Анализ языков

Valio индексирует исходные файлы C, C++, C#, Java, JavaScript и TypeScript и
добавляет к каждому поддерживаемому файлу синтаксический отчёт, если включён
вспомогательный анализатор. Это наблюдение над AST, а не результат компиляции.
Оно помогает находить написанные объявления в разных репозиториях и не выдаёт
неразрешённые сведения за точные факты.

## Что происходит при индексации

1. `valio-agent index` получает Git worktree, применяет политику для исходников
   и конфигурации и загружает принятый снимок.
2. API назначает неизменяемые идентификаторы файлов и представления. Поддержанные
   исходные файлы передаются вспомогательному Tree-sitter WebAssembly-анализатору.
3. Отчёт проверяется по переданному пути и исходной длине в байтах UTF-8, затем
   сохраняется вместе с неизменяемым артефактом в SurrealDB.
4. Зафиксированное представление обслуживает обычный поиск по исходникам и
   символам, а также отдельный синтаксический запрос. Запрос возвращает отчёт,
   сохранённый для этого представления, и не разбирает текущую рабочую папку
   разработчика.

DSL поиска по исходникам подходит для точного поиска текста и символов. Например,
`symbol:User` ищет написанные символы в выбранном неизменяемом представлении.
Синтаксический запрос нужен, когда требуется контур объявления или метаданные
написанного члена.

## Поддерживаемые пути

| Расширение | Язык при индексации | Синтаксическая грамматика |
| --- | --- | --- |
| `.c`, `.h` | C | C |
| `.cpp`, `.cc`, `.cxx`, `.hpp`, `.hxx`, `.hh` | C++ | C++ |
| `.cs` | C# | C# |
| `.java` | Java | Java |
| `.js`, `.mjs`, `.cjs`, `.jsx` | JavaScript | JavaScript; JSX для `.jsx` |
| `.ts`, `.mts`, `.cts`, `.tsx` | TypeScript | TypeScript; TSX для `.tsx` |

`.h` намеренно считается C. Заголовок C++ неоднозначен без конфигурации
компилятора, поэтому Valio не угадывает его язык. Остальные расширения остаются
исходным текстом с языком `text` по умолчанию и без синтаксического отчёта.

## Данные синтаксического отчёта

Отчёт использует исходные полуоткрытые диапазоны байтов UTF-8. В нём есть классы,
интерфейсы, структуры, перечисления и их элементы, поля, свойства, функции,
методы, связь с родительским объявлением, явно написанные типы, параметры,
видимость, модификаторы и прямые атрибуты. Списки атрибутов сохраняют буквальную
запись, включая цели и аргументы атрибутов C#. У C#-перечисления поле
`underlyingType` появляется только когда базовый тип, например `byte`, явно
написан в объявлении.

Наблюдения идентификаторов и синтаксические вызовы имеют
`resolution: "unresolved"`. Директивы C# `using` и инструкции TypeScript `import`
сохраняются как синтаксические импорты. Это полезное свидетельство навигации, но
не утверждение, что импорт, вызов, имя типа или использование перечисления
разрешается в единственный символ.

Отчёт не выводит layout, смещения, выравнивание, выбор перегрузки, наследование,
псевдонимы, межфайловые символы, цели вызовов, точные использования enum или
графы управления и потоков данных. Отсутствующее поле означает неизвестность, а
не доказательство отсутствия.

## Запрос к зафиксированному представлению

Из корня репозитория создайте или обновите представление нативным агентом:

Сначала зарегистрируйте `example-repository` и `example-project` с корнем
исходников через работающий API или web-интерфейс. Путь должен указывать на
существующий Git worktree.

```powershell
$env:VALIO_API_TOKEN = 'valio-local-development-token-0001'
go -C src/back-end run ./cmd/valio-agent index `
  --root C:\work\example `
  --server http://127.0.0.1:8080 `
  --repository example-repository
```

Сохраните возвращённый `viewId` и передавайте его во всех запросах чтения. Этот
PowerShell-запрос находит файлы, в сохранённом синтаксическом отчёте которых есть
написанное имя `User`:

```powershell
$headers = @{ Authorization = 'Bearer valio-local-development-token-0001' }
$body = @{
  scope = @{ workspaceId = 'workspace-main'; projectIds = @('example-project'); viewId = 'pinned-view-id' }
  name = 'User'
} | ConvertTo-Json -Depth 6
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8080/api/v1/syntax/query `
  -Headers $headers -ContentType 'application/json' -Body $body
```

Инструмент MCP называется `syntax_query`. Передайте тот же `scope` и необязательный
`name` или `fileId`; например, клиент отправляет
`{"scope":{"workspaceId":"workspace-main","projectIds":["example-project"],"viewId":"pinned-view-id"},"name":"User"}`.
Устаревший `GET /api/v1/types` пока работает только для Go и не служит заменой
разрешению типов C, C++, C#, JavaScript или TypeScript.

## Включение нативного анализатора

Docker Compose уже включает среду Node и зависимости анализатора. Для нативного
процесса API установите Node.js 26.8.1 и подготовьте анализатор до запуска API:

```powershell
Push-Location src/back-end/analyzers/syntax
npm ci
npm test
Pop-Location
$env:VALIO_SYNTAX_HELPER = (Resolve-Path src/back-end/analyzers/syntax/index.js).Path
$env:VALIO_NODE_BINARY = 'node'
go -C src/back-end run ./cmd/valio-api
```

`VALIO_SYNTAX_HELPER` читается при запуске API. Проверка при старте загружает
грамматику TypeScript, поэтому отсутствие Node, несовместимый файл грамматики или
недоступный анализатор останавливают запуск. Во время индексации ошибка анализатора
останавливает публикацию вместо создания представления, которое якобы содержит
синтаксические данные. Диагностика разбора неверного исходника явно остаётся в
сохранённом частичном отчёте.

Представления, созданные до включения синтаксического анализа, не получают отчёты
задним числом. После включения анализатора снова проиндексируйте исходники, чтобы
создать новое представление.

## Проверки принятия

Запустите проверки из корня репозитория:

```powershell
.\scripts\test-integration.ps1
.\scripts\smoke.ps1
```

Интеграционный сценарий устанавливает зависимости анализатора и запускает его
грамматические фикстуры. Smoke-сценарий загружает небольшой многоязычный набор и
проверяет поиск по исходникам и символам, синтаксические отчёты,
retrieval/context и локальные графовые данные Go в возвращённом зафиксированном
представлении.
