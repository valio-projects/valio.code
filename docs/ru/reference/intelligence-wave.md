# Волна интеллектуального анализа: возможности и границы

`valio.code` — локальный вертикальный срез, а не полная v1-реализация анализа
или поиск промышленного масштаба. См. [анализ языков](language-analysis.md),
[AI-провайдеры эмбеддингов](../getting-started/ai-providers.md) и проверяемый
[пример AI-профилей](../../../deploy/ai-profiles.example.json).

## Текущие возможности

Неизменяемый view проекта хранит исходники, AST-фрагменты, символы и факты
связей. Go использует частичный локальный анализ `go/types` для межфайловых
символов, ссылок, вызовов, чтений и записей. C, C++, C#, Java, JavaScript,
TypeScript, TSX и JSX добавляют проверенные синтаксические отчёты и
TypeDescriptor с написанными членами, параметрами, типами возврата, видимостью,
модификаторами и raw syntax атрибутов.

`/api/v1/types` и MCP `type_query` выдают эти описания. Описание типа не-Go —
синтаксическое свидетельство: в нём нет компиляторно разрешённого символа,
ABI/layout, вычисленного значения enum, цели overload или межфайлового
разрешения типов и вызовов. Явное выражение enum остаётся выражением; неявные
значения и generics, которых нет в отчёте helper, остаются неизвестными.

AST-фрагменты методов не-Go поддерживают ограниченное расширение контекста
родителя. `/api/v1/structure/graph` и MCP `structure_graph` выдают containment
объявлений, членов и параметров, а также observations import и call со статусом
unresolved. В MCP теперь 19 инструментов.

Retrieval объединяет лексический BM25, символы, структурных кандидатов по
нормализованному хешу, семантическое ранжирование точным cosine,
reciprocal-rank fusion и необязательный reranker. Структурный поиск не является
общим MinHash, а точный cosine не означает HNSW.

## Свидетельство AI-провайдера

JSON-профили настраивают Ollama, LM Studio/OpenAI-compatible, удалённые и
Docker-host провайдеры. Smoke использовал `qwen3-8b-lmstudio-docker` (Q8_0,
4096 измерений) в проекте `demo-6ebf95f8fc7e`, view
`7e6eddbb4543be8e0bb330ecd5ab65f81c6ce9cdf3b1019da69a767f52f7e93f`.
Он сохранил 29 code embeddings и выполнил semantic и hybrid retrieval. Это
проверяет локальный путь провайдера, а не доступность удалённого сервиса или
качество поиска.

## Граница типизированного CBOR SurrealDB

В JSON RPC SurrealDB 3.2.4 действует устаревшее приведение: `id: number`
становится record ID `id:number`. Записи Repository теперь используют
типизированный CBOR через закреплённый SDK codec. Регрессия проверяет строки,
похожие на исходный код, UUID, даты и Unicode, а также 64-битные целые, чтобы
они сохраняли своё типизированное представление.

## Статус приёмки

| Область | Текущее состояние | Граница |
|---|---|---|
| Go | Локальные межфайловые факты через `go/types` | Нет полной поддержки внешних пакетов и build tags. |
| C/C++/C#/Java/JS/TS/TSX/JSX | Проверенный синтаксис, TypeDescriptor и не-Go AST-фрагменты методов | Нет компиляторной семантики, CFG/DFG и межфайлового разрешения. |
| API типов и структуры | `/types`, `type_query`, `/structure/graph`, `structure_graph` прошли Windows-тесты и smoke | Нет заявления о compiler resolution или семантическом графе. |
| Retrieval | BM25, символы, структурные кандидаты, точный cosine, hybrid RRF, необязательный reranking | Нет заявления о масштабе, HNSW или качестве поиска. |
| Профиль LM Studio | Docker-host Q8_0, 4096 измерений, 29 сохранённых code embeddings и semantic/hybrid retrieval | Digest модели и удалённые провайдеры контролирует оператор. |

## Проверка

Windows прошёл `go test ./... -count=1` и `go vet ./...` с реальными SurrealDB
3.2.4 и Jaeger, включая syntax integration. Docker собрал образы API, worker и
migration, а `docker compose up -d --wait` запустил сервисы с успешными проверками готовности.
Linux Docker прошёл `go test -race ./...`; зависящие от базы тесты в этой
сборке пропускаются.

`scripts/smoke.ps1` проверил семь описаний типа User, шесть графов объявлений
для языков помимо Go, поиск, чтения полей Go, фильтрацию конфигурации и
идемпотентность. Снимок, созданный версией `87d2c0b`, по-прежнему возвращает
один Go-тип и пять результатов лексического поиска. Паритет MCP/HTTP прошёл для `structure_graph`, `type_query`,
`code_search`, `retrieval_search` и `symbol_search`; optional-field fix делает
MCP defaults такими же, как HTTP.

## Что остаётся

Для полной v1 ещё нужны семантика уровня SCIP для пяти языков, CFG и
межпроцедурный анализ, связи SQL/API/events, интеллект тестов и истории.
Возможности на основе GNN — исследование после v1. Контракт или пункт roadmap
не доказывает, что эта функция уже работает.
